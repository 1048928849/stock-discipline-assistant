# 下一阶段架构分析与实施路线

## 1. 现状结论

`refactor/strategy-engine-v2` 已在 `origin/main` 之上完成 Feature、Strategy、PricePlan、Risk、Decision、Repository、事务、规则版本、策略版本和 Research Platform 分层。当前分支不是待重建的原型；下一阶段必须沿用这些领域边界。

当前仍有四个业务缺口：

1. PricePlanner 的正式交易价格仅来自平台上下沿、近10日低点和 ATR，没有资金成本锚的时间衰减、成交密集峰与多锚共振。
2. Risk Engine 只计算单次入场容量，缺少账户回撤熔断、组合风险预算、相关板块合并敞口和跳空/跌停压力测试。
3. Decision Engine 只裁决单时点结论；完整建仓和卖出过程仍散落在 Decision 与 `plan_execution.py` 的自由字符串中。
4. Research Platform 能保存验证记录，但尚无统一的样本切分、成本/滑点、前视偏差检查和策略晋级门槛。

## 2. 本阶段已实现：动态资金成本锚只读切片

新增纯计算 `capital_anchor_engine`，输入标准 OHLCV 与平台事实，输出：

- 20/60/120 日滚动成交量加权成本；
- 近120日成交量分布的三个密集峰；
- 平台上沿、平台下沿结构锚；
- 以 ATR 与价格比例共同确定聚类容差的支撑/压力区；
- 基于最高置信核心支撑区的极限止损候选；
- 锚来源、权重、窗口、区域置信度和组成锚 ID。

该结果挂在 `PricePlan.market_structure`，但不替换冻结的 `stop_price / target / entry_zone`。原因是极限止损若直接成为仓位公式输入，会同时改变风险预算、数量、状态与 Golden Master；必须先完成历史验证与影子比较。

## 3. 目标调用链

```text
OHLCV / 事件数据
  -> FeaturePipeline
  -> CapitalAnchorEngine（成本锚、成交密集峰、锚有效性）
  -> PricePlanner（支撑/压力/结构失效/极限止损候选）
  -> StrategyEngine（入场触发是否成立）
  -> PortfolioRiskEngine（账户是否允许承担新风险）
  -> TradeLifecycleStateMachine（当前允许的唯一状态迁移）
  -> ValidationRunner（影子结果、回测、走样监控）
```

AI 仍只读取冻结结果做解释，不能改变锚、点位、仓位、状态或验证结论。

## 4. 后续任务顺序与验收条件

### P1：成本锚验证与正式价格规则（事件锚影子计算已完成）

- 增加事件日 VWAP 输入协议，事件必须有 `event_id / event_time / source_id`。
- 为锚增加半衰期、跌破后接受度和支撑/压力角色转换。
- 在不少于三类市场环境中影子比较旧止损与候选止损。
- 只有样本外最大回撤、期望值和尾部损失均不恶化，才创建新策略版本切换正式字段。

当前已经实现：

- 从异常收益和异常成交量筛选事件日，不简单选最近日期；
- 开盘至10:00、10:30、上午、下午和全日VWAP；
- 大宗交易等带`source_id`的机构交易价格证据；
- 按ATR和价格比例聚类，跨事件日期会提高置信度；
- `RESISTANCE_FROM_BELOW / SUPPORT_FROM_ABOVE / SUPPORT_AFTER_BREAKOUT / RESISTANCE_AFTER_BREAKDOWN / CONTESTED`角色；
- 分钟K线和机构证据数据库表，以及生产价格计划读取链路；
- 缺少分钟数据时只返回`missing_data`和降级警告，不生成虚假阶段VWAP。

中际旭创Golden边界使用7月28日分钟成交输入和7月17日979.46大宗交易输入，要求算法独立得到约980—982的上午成本并形成跨事件压力簇。该测试验证计算和防硬编码边界，不代表已经取得生产级实时数据授权。

### P2：账户级风险引擎（领域与生产上下文已接通）

- 输入开放风险、行业/主题聚合敞口、账户峰值权益和连续亏损状态。
- 输出单笔、组合、行业、现金、回撤熔断六类约束。
- 压力场景至少覆盖跳空 -3%/-5%、一字跌停无法成交、板块同步下跌。
- 风险引擎只缩小或阻断仓位，不得放宽 PricePlanner 的结构失效位。

已实现账户权益历史表、账户更新时的权益快照、峰值回撤、组合开放风险、持仓止损完整性、连续亏损风险折扣，以及 -3%/-5%/-10% 跳空损失。生产计划链路会阻断缺失持仓止损、组合开放风险超限和回撤熔断情形，并通过 `account_risk` 输出审计结果。

### P3：交易生命周期状态机（兼容映射已完成）

- 领域状态统一为 `WATCH / READY / TRIAL / CONFIRMED / HOLD / REDUCE / EXIT / CLOSED`。
- 显式定义允许迁移、触发证据、幂等事件和禁止迁移。
- 建仓只允许盈利或结构继续确认后增加风险；禁止亏损补仓。
- 卖出流程区分分批减仓、结构退出、硬止损和极限情景退出。
- ORM 旧状态通过兼容映射迁移，API 版本不静默改变。

已实现八个目标状态、显式事件迁移、旧状态兼容映射和历史事件链审计。执行详情同时返回旧 `execution_status` 和新 `lifecycle_state`，不重写历史记录；加仓必须满足触发确认、结构完整且持仓盈利。

### P4：验证框架（核心门槛已完成）

- 时间序列 walk-forward，训练/验证/样本外严格按时间分割。
- 模拟复权、手续费、滑点、T+1、涨跌停、停牌与成交量容量。
- 报告期望值、最大回撤、Calmar、利润因子、连续亏损、尾部损失和市场分层表现。
- 策略版本只有通过预定义门槛才能从 DRAFT 晋级 ACTIVE；失败记录追加保存，不能覆盖。

已实现严格交易日期校验、walk-forward时间切分、手续费/滑点后的期望值、利润因子、最大回撤、尾部损失、环境样本统计和验证报告追加保存。策略从SHADOW激活时，必须存在样本量不少于30的PASSED验证记录。

## 6. 剩余的真实数据工作

架构和强制边界已经闭环，但不能把框架测试当作策略已被市场验证。仍需配置能够合法稳定提供分钟行情、龙虎榜和大宗交易的数据源，并采集足够历史信号，按真实A股T+1、涨跌停、停牌和成交容量生成 ValidationTrade；动态极限止损只有在样本外表现不恶化后才能创建新策略版本并替换正式止损。

## 5. 不应做的事情

- 不把“锚附近”直接解释成必然支撑。
- 不用全样本调参后再用同一数据宣称有效。
- 不因新状态机重写已确认计划的历史事件。
- 不让账户级风控、AI 或前端绕过领域层直接修改止损和仓位。
